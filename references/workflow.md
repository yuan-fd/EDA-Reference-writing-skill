# 工作流程、核查与验收

## 1. 确认真正生效的内容

识别主文件、活动 `\input` / `\include`、`thebibliography`、自动 bibliography 命令和图表源。优先 `rg` 搜索，再读上下文。

同名 v4 可能改过多次；Downloads 文件可能比在线项目旧。用实际输入关系及文本确认，不能凭文件名猜。三个 reference 文件可能分别是活动手写条目、历史手写条目、未启用 `.bib`，不等于编译三套。

检查活动输入是否注释、大小写与路径是否正确。只有 PDF 时可检查可见编号和内容，不能声称检查过源码引用键或编译输入。在线连接不可用时先做可完成部分，不编造同步结果。

## 2. 分层处理

用户确认的处理次序是：**格式 → 重复 → 链接和出版信息核查**。

独立读取可以批量进行；有依赖的修改及在线写入顺序执行。少数未找到的页码不拖住所有格式修正；已接受省略的页码不每轮重列为缺陷。

### 格式

逐条核对类型、作者、标题、引号、会议/刊名、卷期年份、页码、链接策略、标点与空格。具体说明 W/F/K 哪层依据，不只写“按国际规范”。

### 重复

区分：

- 同一论文重复录入：以标题、作者、年份、DOI/arXiv 交叉确认再合并。
- 预印本与正式版：同一对象且正式版已确认可优先正式版；正文讨论特定版本独有内容则需要判断。
- 论文与软件/数据集 artifact：可为不同引用对象，不当然重复。
- 同作者同年不同论文、不同作者缩写相同：不当然重复。

合并前搜索所有旧键调用，更新正文和图表后再删重复项。不能按相似标题直接批删。

### 元数据与入口

优先出版商记录、会议录/官方页面，其次作者页面或作者 PDF、arXiv、DBLP/Crossref 等索引。搜索摘要定位，不作唯一证据。软件版本查实验脚本、日志或用户确认，不从最新 HEAD 反推。

按字段记录已确认/未确认；找到标题不等于整条都核实。正文描述的对象与条目必须一致。

链接存在性、指向正确性和当前可达性分开：付费墙、403、登录或网络问题不自动说明 URL/DOI 错误；能打开也不证明版本正确。作者明确 DOI 注册未完成则不填。显示格式仍按本 skill 的依据顺序。

页码查不到时核对正式记录与作者版，用户要求停止找就停止。本项目五条缺页码最终省略，不能反复“修复”回 9 pages。

## 3. 最小修改

用户要求先给方案时，列：条目、原写法、建议、依据、是否影响正文引用。授权后执行，不重问已批准的同一事项。

每次修改一个 reference 条目或一个正文句子，先读最新原文、比较目标内容。发现合作者新编辑时重新合并，不用本地旧全文件覆盖在线源。

键尽量不变；确需变化时：

1. 搜索全部调用，包含 caption、表格、TikZ、输入文件。
2. 建旧键 → 新键映射，处理同作者同年冲突。
3. 逐处同步。
4. 查旧键残留、缺项和重复定义。

避免部分键替换误伤更长键、URL 或标题。不为了格式整洁批量重命名所有键。

仅键变化无需重写正文；预印本升级正式出版时，查正文是否仍说 preprint、旧年份或旧状态，只改必要句子。

修改到的正文一句一源码行，不 reflow 整篇。reference 可按作者/标题/出版信息分行，不为“一句话一行”把全条挤成一行。

## 4. 在线编辑与文件管理

用当前可用浏览器/编辑器工具定位和逐项修改；失败后可用已授权 GUI，不反复折腾权限。先确认正确项目和文件，不假设旧标签序号、选择器、临时工具路径或连通状态永久有效。

保留历史文件但不编译。恢复已删旧文件时找真实历史或确切原件，不能把 v4 换名叫 v3。不得无必要生成多套 corrected/preview/vN，造成用户不知道哪个有效。

用户自己粘贴时，说明替换 bibliography 正文/输入文件，不新增第二套环境。避免把独立预览文档的 `\documentclass` 和 `\begin{document}` 粘进主文档。

## 5. 引用完整性

从活动源码建立引用键集合 C 和条目键多重集 B，检查：

- C 无对应条目：缺引用。
- B 内重复键：定义冲突。
- B 无主动调用：未引用条目，结合正文意图处理。
- 改过的旧键仍在活动引用中：同步遗漏。

递归遍历实际参与编译文件，忽略注释、未包含备份和文末无效内容。条件编译、verbatim、自定义引用宏要结合源码判断；简单 regex 只能初筛，不能证明复杂 LaTeX 全部通过。

兼容实际引用命令、逗号分隔多键和可选参数。只有 nocite 不计主动正文引用；图中真实引用计入。

额外查 `[?]`、`[??]`、可疑手写编号、旧出版状态。PDF 没有问号不能代替源码闭合检查。若额外检查 label/ref，报告时与文献键分开说明。

## 6. 编译与目视

用项目真实编译路径，在相关修改完成后编译并完成所需引用更新，再读最终日志。无需每改一个逗号全量编译。

缺文件、undefined citation、重复定义、编译中断必须处理。Underfull 可能仅信息，结合目视；0 error 不证明题名、年份、版本或版权正确。

查看全部 reference 页面及引用变化的正文/图表页：

- 编号连续，条目完整，引用指向预期工作。
- 双栏顺序、缩进、空格、字号、斜体正常。
- 标题/URL 不超栏、重叠或丢字。
- 重音、连字符、人名真实显示正确，避免提取误判。
- 链接目标正确，句末句号没进入 URL。

右栏续条目接近左栏 References 标题不需“修复”；轻微 Underfull 不用负间距和强行断行消除。

## 7. 结果与发布判断

分开报告：格式、事实元数据、正文引用同步、编译、PDF 目视。只报告实际完成的部分，未核实字段如实说明，不把本次未查的东西一概说错误。

条目数/调用次数只在实际统计后提供，说明活动文件范围。曾经的“42 条 / 67 次”是该稿事实，不是通用验收阈值。

可用汇报：

> 已同步当前活动 reference 与正文/图中的引用键；未发现缺失、重复键或未引用条目。编译及 reference 页面目视通过。未确认正式页码按老师定稿省略。

用户问能否发布时，说明 reference 已完成程度及其他已知真实提交问题；不凭引用检查代替全部科学论据与投稿要求核实。确有版权声明可疑等证据可单列，不擅改版权，也不追加泛泛清单。

默认交付一个有效文件与简短逐项说明；独立预览/打包仅按用户需要。不要反复把已接受且无须解决的情况列作未决项。
